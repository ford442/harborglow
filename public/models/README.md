# Ship hull GLBs

Files in this folder are **LOD0** hulls for HarborGlow. Distant ships stay
procedural (`Lod2Impostor`). If a GLB fails to load, the game falls back to the
blueprint mesh — see `ShipModelBoundary`.

## Status of these meshes

All twelve are **placeholders**, and they are **unlit**
(`KHR_materials_unlit`) — they do not respond to the harbour's night lighting or
the light-show emissive drive except via `emissive_`/`glow_` name matching. An
authored replacement must be **lit PBR** (`MeshStandardMaterial` metal-rough) or
it will read flat in exactly the scenes the game is built around.

Replacements must keep the **same** root node (`{shipId}_root`), `Empty_HP_*`
hardpoint names, and `attachmentSocketMap` bindings.

## Compression

**No Draco.** The Draco decoder is only distributable as a separately hosted
WASM bundle, so a Draco hull would need a third-party CDN request at runtime and
would silently fall back to a procedural ship wherever that CDN is blocked.
`npm run models:verify` fails the build on any committed
`KHR_draco_mesh_compression` asset.

Uncompressed is fine at current sizes. Meshopt (`npm run models:compress`) is
supported — its decoder is bundled with three, no hosted path.

## Budgets, enforced by `npm run models:verify`

- **≤ 64 primitives per hull** and **≤ 320 across the fleet** — a glTF primitive
  is a draw call, and the whole fleet can be docked at once. Today: 201.
- **≤ 24 materials per hull.**
- Byte size is **reported, not gated** by the draw-call check — file size does
  not predict frame cost (`oil_tanker.glb` is 46 kB and 17 draw calls). Gzip
  size is separately budgeted by `npm run models:check-size`.
